# 울산대 공지·비교과 → 노션 자동 수집기

울산대 사이트 4곳의 비교과 프로그램과 공지를 1시간마다 모아 노션 데이터베이스 하나에 넣습니다.
AI 없이 파이썬 코드로만 수집하고, 비용은 0원입니다. 자세한 설계는 [`PLAN.md`](PLAN.md)에 있습니다.

| 출처 | 넣는 기준 | 노션 `주관부서` |
|---|---|---|
| U-STEP 학생 비교과 | 신청 마감 전이고, 신청 시작일이 최근 2개월 안 | U-STEP |
| ICT융합학부 공지 | 작성일이 최근 1개월 안 | ICT융합학부 |
| IT융합전공 공지 | 작성일이 최근 1개월 안 | IT융합전공 |
| SW중심대학사업단 공지 | 작성일이 최근 1개월 안 | SW중심대학사업단 |

- 같은 글은 두 번 들어가지 않습니다. 사이트에서 제목이나 기간이 바뀌면 노션 행도 고쳐집니다.
- 노션에 링크를 뺀 모든 값이 같은 행이 여럿 있으면 하나만 남깁니다. 이름과 기간이 같은 U-STEP 분반도 한 행으로 합쳐집니다.
- ICT융합학부와 IT융합전공에 제목과 게시된 날짜가 같은 공지가 있으면 ICT융합학부 것만 남깁니다(`config.yaml`의 `cross_source_dedup`).
- `게시된 날짜`가 3개월 지난 행은 노션 휴지통으로 옮깁니다(30일 안에 복구 가능). U-STEP은 신청 마감이 지난 행만 옮깁니다.
- **`링크`가 비어 있는 행(직접 입력한 행)은 절대 건드리지 않습니다.**
- **관심 없는 행은 노션에서 직접 지우시면 됩니다. 다시 생기지 않습니다.** 프로그램은 한 번 본 글을 `state/seen.json`에 기록하고, 새로 나온 글만 넣습니다.

## 노션 데이터베이스

| 열 | 타입 | 내용 |
|---|---|---|
| 공지사항 | 제목 | 공지 제목 / 프로그램명 |
| 주관부서 | 선택 | 위 표의 출처 이름 (프로그램이 출처 구분에 사용) |
| 게시된 날짜 | 날짜 | 공지 작성일 (U-STEP은 수집한 날) |
| 신청기간 | 날짜 | U-STEP만 |
| 운영기간 | 날짜 | U-STEP만 |
| 링크 | URL | 원문 주소 |
| 수집 일시 | 생성 일시 | 행이 DB에 추가된 날짜·시간 (노션이 자동으로 채움) |

열 이름을 바꾸면 `config.yaml`의 `notion.columns`도 같이 바꿔야 합니다. 열 이름이나 타입이 맞지 않으면 프로그램은 아무것도 쓰지 않고 멈춥니다.

## 로컬에서 실행

Python 3.12가 필요합니다.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # 그다음 .env에 토큰과 DB ID를 직접 입력
```

| 명령 | 동작 |
|---|---|
| `.venv/bin/python -m src.main --dry-run` | 노션에 쓰지 않고, 추가·갱신·삭제될 목록만 출력 |
| `.venv/bin/python -m src.main` | 실제 반영 |
| `.venv/bin/python -m src.main --no-delete` | 추가·갱신만 하고 삭제는 건너뜀 |
| `.venv/bin/python -m src.main --only IT융합전공` | 사이트 하나만 실행 |
| `.venv/bin/pytest` | 테스트 (네트워크·노션 없이 실행됨) |

종료 코드는 `0`이면 정상, `1`이면 사이트나 노션 중 하나가 실패, `2`면 설정 오류입니다.

## 노션 Integration 준비

1. https://www.notion.so/profile/integrations 에서 **내부** 통합을 만듭니다.
2. 기능(Capabilities)은 **콘텐츠 읽기·업데이트·삽입만** 켭니다. 댓글은 끄고, 사용자 정보는 "없음"으로 둡니다.
3. 데이터베이스 페이지 `···` → **연결**에서 이 통합을 추가합니다. 상위 페이지가 아니라 **데이터베이스 하나에만** 연결합니다.
4. 토큰(`ntn_...`)은 `.env`나 GitHub Secrets에만 넣습니다. 채팅, 코드, 커밋 메시지에는 넣지 않습니다. 유출이 의심되면 노션에서 바로 재발급합니다.

> 자동 실행이 매시간 `state/seen.json`을 커밋하므로, 로컬에서 코드를 고쳐 push하기 전에는 `git pull --rebase`를 먼저 하세요.
> 로컬에서 dry-run이 아닌 실제 실행을 하면 로컬 기록 파일도 바뀝니다. 이 경우 `git checkout state/seen.json`으로 되돌리고 pull하면 됩니다.

## GitHub Actions 자동 실행

`.github/workflows/crawl.yml`이 매시 17분(UTC)에 실행됩니다.

1. 저장소를 만들고 Settings → **Code security**에서 아래를 켭니다.
   - Secret scanning
   - Push protection
   - Dependabot alerts
2. Settings → **Secrets and variables → Actions**에 다음 두 값을 등록합니다.
   - `NOTION_TOKEN`
   - `NOTION_DATABASE_ID`
3. Actions 탭 → **crawl** → **Run workflow**로 한 번 수동 실행해서 확인합니다.

워크플로는 아래 원칙으로 작성되어 있습니다.
- 수집 작업은 저장소 읽기 권한만 갖습니다. 기록 파일 커밋은 별도 작업(`save-state`)이 하고, 쓰기 권한은 그 작업에만 있습니다. 이 작업은 기록 파일만 커밋하고 다른 변경이 있으면 거부합니다.
- GitHub 공식 Action만 쓰고, 커밋 해시로 고정합니다.
- 테스트가 실패하면 노션에 쓰지 않습니다.
- 실행이 서로 겹치지 않게 합니다.

비용과 운영에 대해:
- 공개 저장소는 무료입니다. 비공개 저장소는 월 2,000분까지 무료이고, 1시간 간격이면 약 720분을 씁니다.
- Settings → Billing에서 Actions 지출 한도가 `$0`이면 무료 시간을 넘어도 요금이 나가지 않고 실행만 멈춥니다.
- 실패하면 GitHub가 기본 알림 메일을 보냅니다.
- 공개 저장소는 60일 동안 커밋이 없으면 예약 실행이 자동으로 꺼집니다. Actions 탭에서 다시 켜면 됩니다.
- GitHub 서버는 해외에 있습니다. 학교 사이트가 해외 IP를 막으면 실패하는데, 그때는 맥의 `launchd`로 로컬에서 실행하는 방법이 있습니다(PLAN.md 6장).

## 보안·개인정보

- HTTPS 인증서 검증은 끄지 않습니다.
- 노션에 넣는 링크는 `https://*.ulsan.ac.kr`만 허용합니다.
- 작성자 이름 같은 개인정보는 수집하지 않습니다. SW중심대학사업단 API가 함께 내려 주는 교직원 실명도 읽지 않습니다. 테스트용 응답(`tests/fixtures/`)에서도 지운 뒤 저장했고, 테스트로 확인합니다.
- 로그와 오류 메시지에는 상태 코드와 짧은 메시지만 남깁니다. 토큰, DB ID, 응답 전체는 남기지 않습니다.
- 한 번 실행에서 삭제 대상이 50건을 넘으면 아무것도 쓰지 않고 멈춥니다.
- 연결 오류가 나면 2초 뒤 한 번 더 시도합니다. 단, 노션 행 생성은 중복이 생길 수 있어 재시도하지 않습니다(다음 실행이 채웁니다).

## 사이트 추가

1. `src/sources/`에 `fetch_raw(cfg, session)`와 `parse(raw, cfg)`를 가진 모듈을 만들고, `src/sources/__init__.py`의 `REGISTRY`에 등록합니다.
2. `config.yaml`의 `sources`에 한 줄을 추가합니다. 같은 시스템을 쓰는 게시판이라면 이 단계만 하면 됩니다(예: `ulsan_board`).
3. 노션 `주관부서` 열에 같은 이름의 선택지를 추가합니다.
4. `.venv/bin/python -m tests.make_fixtures`로 테스트용 응답을 저장하고 파싱 테스트를 추가합니다. 작성자 정보가 지워졌는지 꼭 확인합니다.
